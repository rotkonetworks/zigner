Module frost_storage

Expand description

FROST key shares at rest.

A FROST share has no seed phrase behind it: it exists only in this device’s database, so it used to sit there as plaintext JSON. It is now sealed with XChaCha20-Poly1305 under a key derived from one of the device’s seeds, the seed the user already backs up:

  key  = HMAC-SHA512("zigner-frost-storage-v1", seed)[..32]
  aad  = "zigner-frost-v1" || wallet_id
  blob = version(1) || nonce(24) || ciphertext+tag

The wallet id in the associated data stops one wallet’s sealed secrets being moved onto another wallet’s row. The record keeps a fingerprint of the sealing seed so the right seed is found on a device with several.

Reading a share therefore needs the seed, which needs the unlock prompt. A wallet stored before sealing is sealed the first time its secrets are read with a seed at hand, and only after the sealed copy has been written and read back.

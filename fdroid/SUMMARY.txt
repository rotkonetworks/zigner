CRITICAL BLOCKER
================================================================================

FILE: android/src/main/assets/modules/module0.wasm (2.0 MB)

ISSUE: Prebuilt WebAssembly binary committed to git. F-Droid requires all
       binaries to be built from source during their build process to ensure
       verifiability and prevent malicious code injection.

SEVERITY: BLOCKS SUBMISSION

SOLUTION: Build wasm32-unknown-unknown binary at compile time via Gradle
          prebuild step. Source: rust/pczt_signing/Cargo.toml

TIME TO FIX: 1-2 days (code changes + CI testing)

BUILD IMPACT: Adds ~20-30 minutes to F-Droid's build time (first Rust build)

REFERENCE: Parity Signer (similar Rust+Android app on F-Droid) uses same approach

KEY DECISION POINTS FOR TEAM
================================================================================

1. WASM BUILD IN GRADLE vs F-DROID METADATA

   Option A (RECOMMENDED): Add buildWasm task in android/build.gradle
   - Pros: Works anywhere, faster local builds
   - Cons: Slightly heavier build.gradle

   Option B: Only specified in F-Droid metadata
   - Pros: Clean source tree
   - Cons: F-Droid maintainers must manage custom build steps

2. VERSIONING FOR F-DROID

   Current: 0.9.0 (versionCode = 9000)

   If following semantic versioning:
   - v1.0.0 → versionCode = 1000000
   - v1.2.3 → versionCode = 1002003

   The formula in build.gradle (major*1M + minor*1k + patch) works well
   for F-Droid tagging.

3. AUTO-UPDATE STRATEGY

   Recommended: AutoUpdateMode: Version, UpdateCheckMode: Tags

   This means:
   - F-Droid automatically checks GitHub for version tags
   - Any new tag matching v*.*.* triggers a build
   - No manual intervention needed after setup
   - Consider using semantic versioning for clarity
